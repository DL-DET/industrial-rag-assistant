## 2. 阶段一：P0 地基（1~2 天）

**Step 0：先保住退路**

```powershell
cd D:\python\RAG智能体实战代码
git init
git add .
git commit -m "chore: baseline before refactor"
git tag baseline-v1
git switch -c refactor/eval-first
```

**Step 1：评测集（最高优先级，先于任何优化）**

- 新建 `eval/` 目录
- `eval/dataset.jsonl`：50 条，字段 `{id, question, ground_truth, gold_sources:[{file,page}], answerable: bool}`
  - 40 条有答案（覆盖参数查询 / 维护周期 / 故障排查 / 安全规范）
  - 10 条无答案（考拒答：问知识库外的设备、未来日期、无关领域）
- `eval/metrics.py`：`recall@k`、`MRR`、`hit_rate`
- `eval/run_eval.py`：跑检索 → 出 `eval/report.md` 表格
- `eval/judge.py`：LLM-as-judge 打 faithfulness / answer_correctness，再用人工抽检 20 条校准

验收：`python -m eval.run_eval` 能输出一张基线表格，贴进 README。

**Step 2：阈值 + 拒答**

- `config_data.py` 新增 `RETRIEVAL_SCORE_THRESHOLD`（默认 0.35，用评测集调）
- `vector_stores.py` 改用 `similarity_search_with_relevance_scores`
- 低于阈值 → 直接返回「知识库暂无足够依据」，**不调用 LLM**
- 验收：10 条无答案问题拒答率 ≥ 90%，且 40 条有答案问题不误杀

**Step 3：历史裁剪**

- `file_history_store.py` 增加 `max_turns`（默认 6）
- `rag.py` 只取最近 N 轮；超长时用「前情摘要 + 最近 3 轮」
- 验收：连续 30 轮后 prompt token 稳定在阈值内

**Step 4：入库原子化 + 版控**

- `doc_id = sha256(文件名 + 业务版本号)`，metadata 加 `doc_id / version / effective_date / equipment_model / section`
- 先 `delete(where={"doc_id": ...})` 再 `add_texts(..., ids=[stable_ids])`，最后写指纹
- md5 状态从纯文本行改为 `state/ingest.jsonl`（含时间、doc_id、chunk 数），写入用原子替换
- 新增 `delete_document(doc_id)`、`list_documents()`，UI 上给「知识库文件列表 + 删除」
- 验收：同一份手册传 v1 再传 v2，检索只命中 v2

**Step 5：埋点**

- `logger_handler.py` 接进来（替代 st.error 兜底）
- 每次问答落 `logs/qa.jsonl`：`session_id, question, retrieved_ids, scores, prompt_tokens, completion_tokens, first_token_ms, total_ms`
- README 出一张「成本与延迟分布」表

## 7. 风险与注意

- 评测集是自己标的，有偏；必须写明标注口径与人工校准比例
- LLM-as-judge 有波动，同一批样本跑 2 次取均值
- 每次优化前后都要在同一份评测集上跑，禁止换题
- 模型调用有成本，评测跑批前先估算调用次数（50 题 × 2 次 ≈ 100 次调用）
- 重构期间保持 `main` 可运行，所有改动走 `refactor/*` 分支
